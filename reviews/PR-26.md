### [P2] Sign-out navigates even if server sign-out fails
- Category: defect
- Rule: AUTH-13
- Evidence: `apps/web/src/app/(app)/sign-out-button.tsx:14-16` awaits `authClient.signOut()` but ignores its returned error before pushing `/sign-in` and refreshing. There is no failure message or pending reset.
- Failure scenario: The auth request fails transiently, the button still sends the user to sign-in while their server session remains live, and the pending button stays disabled if navigation does not complete.
- Why it matters: The UI indicates a completed sign-out without confirming that the server session was cleared.
- Required correction: Navigate only after confirmed sign-out; on failure, keep the current page, show a retryable error and re-enable the button.
- Owner: builder
- Verification: Force the sign-out request to fail in a browser and confirm the session is still clearly active and retry works; verify successful sign-out clears server session and navigation state.

- Category: resilience / usability
- Rule: Phase 0 plan Task 13 failure paths

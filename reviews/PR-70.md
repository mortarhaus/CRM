### [P3] The QR is put to storage while the settings row is locked
- Evidence: `changePaymentDetails` takes `getSettings(tx, { forUpdate: true })`, then `makePatch()` does `storage.put` (up to 2 MB) inside the transaction. A slow S3 holds the row lock and a pooled connection, blocking every other settings save of the workspace.
- Suggested correction: read and validate the bytes and put the object before the transaction (content-addressed and never deleted, so an orphan from a refused save is harmless), then only set the key inside it. Optional.
- Status: open (optional)

### [P3] `last4` of a short or formatted number
- Evidence: `value.slice(-4)` on the raw text: a 4-character number is stored whole; "…-789" stores the dash. Suggest taking the last 4 digits after removing spaces and dashes, and storing nothing when there are fewer than 8 digits. Optional, and the open ASK on account-number character rules may settle it.
- Status: open (optional)

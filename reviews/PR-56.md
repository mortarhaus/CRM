### [P2] Without JavaScript, a refused Yes comes back with No selected and the marked field hidden
- Category: guardrail mismatch (P1 by default; lowered to P2 because only the no-JS path is affected, nothing is written, and the Owner can recover by choosing Yes again)
- Rule: FE-32 (forms work without JS), A11Y-03 (errors linked and perceivable)
- Evidence: `apps/web/src/app/(onboarding)/onboarding/onboarding-form.tsx`: the No radio is `defaultChecked` whatever the result, and the tax fields are shown only by `group-has-[#tax-registered-yes:checked]:flex`. Without JavaScript the refused post renders a new document from these defaults, so Yes is unchecked, the block holding the invalid `taxRegistrationNo` field (with `aria-invalid` and its error) is `hidden`, and the alert says "Check the fields marked below" with nothing marked on screen. Anything typed into the registration number, tax name or rate is lost too. The JS path avoids this through `onSubmit` (no form reset). `e2e/onboarding.spec.ts` "without JavaScript" covers only a successful Yes; the refused Yes is tested only with JavaScript on. This comes from reading the code. I did not run it in a browser (no e2e environment in this session).
- Failure scenario: JS off (or the bundle fails to load), the Owner picks Yes, leaves the number empty, submits, and sees an error alert with no visible field to fix and No selected.
- Why it matters: the plan makes this form work without JS (DECISIONS 2026-11-06 item 3), and an error that points at a hidden field fails error identification.
- Required correction: after a refused Yes, the re-rendered form has Yes selected and the invalid field visible with its error. The posted values come back where they're safe to echo (at least the Yes choice; ideally the number, tax name and rate). Add a no-JS e2e case for a refused Yes.
- Owner: builder
- Verification: a new no-JS test in `e2e/onboarding.spec.ts`: Yes with an empty number → alert shown, Yes checked, the number field visible, `aria-invalid="true"`, with the error as its accessible description; then fill it and finish.
- Disposition (P2 only): before merge
- Status: open

### Findings

### [P2] The TEN-10 lint misses some import forms and a new database client
- Category: material risk (enforcement gap; the code today complies)
- Rule: TEN-10, UNI-04, PROJECT.md §9 "no-RLS system tables via the system module"
- Evidence: I ran ESLint with the head config on `apps/web/src/app/(app)/x/actions.ts`. These are **not reported**:
  - `import { getDb } from "../../../db/index.js";` (TypeScript Bundler resolution maps `.js` to the `.ts` file, so this import works).
  - `import { getDb } from "../../../db/";` (trailing slash).
  - `import { createDb } from "@/db/client.js";`.
  - `import postgres from "postgres";` followed by a new client in app code. Nothing bans `postgres`, `drizzle-orm/postgres-js` or `pg` outside `src/db`.
  - For comparison: `@/db`, `@/db/index`, `@/db/client`, `@/db/schema/system`, a deep `@/db/system/workspaces` and a dynamic `import("@/db")` are all reported.
- Failure scenario: a later PR adds a server action that imports `getDb` with a `.js` suffix (some editors auto-insert it), or opens its own `postgres()` client. It then reads `member` or `billing_account` with no RLS and no system-module check. `pnpm lint` stays green.
- Why it matters: the lint is the TEN-10 enforcement the spec names. Today no app code uses these forms. The codebase has no `.js` import specifiers. The only direct client outside `src/db` is `apps/web/worker.ts:6` (the Phase 0 worker stub, pre-existing; PR 5 replaces it).
- Required correction:
  - Let the `directDbSource` regex accept an optional `.js` / `.ts` / `.mjs` extension and a trailing `/`.
  - Ban `postgres`, `drizzle-orm/postgres-js` and `pg` imports in `apps/web` outside `src/db/**` and tests, with a named exemption for `worker.ts` until PR 5.
  - Add the four probes above as fixtures in `lint-rules.test.ts`.
- Owner: builder
- Verification: the four new fixtures are reported, the "allows" cases stay clean, and `pnpm lint` exits 0.
- Disposition: deferred to Phase 1 PR 4 (Task 15, AUTH-01 lint). That is the next PR that edits `eslint.config.mjs`.
- Status: open

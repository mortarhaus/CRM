### [P2] A file renamed into `docs/` or `agents/`, or renamed to `.md`, counts as documentation only
- Category: correctness (the PR's own "unsure means run" rule)
- Evidence: `git diff --name-only` detects renames by default and prints only the **new** path. In a throwaway repo, `git mv apps/a.ts docs/a.ts` gives `git diff --name-only` → `docs/a.ts`, and the head's script prints `false`. A PR that moves a code file out of `apps/` or `packages/` therefore skips the build, Trivy and e2e, although the app changed (a file was removed from it).
- Failure scenario: a cleanup PR moves an unused script or config into `docs/` together with doc edits. The image job is skipped, and a build break first shows up on `main` or the next code PR.
- Required correction: add `--no-renames` to the `git diff` in `code-changed.sh` so both the old and new paths are listed (old path `apps/…` → `true`). One flag.
- Owner: builder
- Verification: rerun the script on a rename range; it prints `true`.
- Disposition (P2 only): before merge
- Status: open

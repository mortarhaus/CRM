### Code review notes (no blocking finding)
- **`NOT_ONBOARDED` (PR #56 P3): resolved.** `save()` reads the row `FOR UPDATE` and refuses before `updateSettings` while `country IS NULL`, for both branding and general. The refusal is thrown by the handler inside `withWorkspace`, so the AUTH-01 order is unchanged. Tests: owner/admin get `NOT_ONBOARDED`, staff get `FORBIDDEN`, and nothing is written.
- **Tax answer:** a Yes needs the number, name and rate (Zod plus the 0026 and 0027 CHECKs). A No clears the default name and rate (0024) and keeps the registration number (Deviation 2; acceptable, and disclosed). The spec matrix doesn't put tax settings under step-up (spec lines 787-798), so AUTH-09 is n-a. Admin and Owner (`minRole: "admin"`) match "Changeable later in settings (admin)" (spec line 731).
- **Migration 0027** `(default_tax_name is null) = (default_tax_rate_bps is null)`: additive. No existing row can violate it (onboarding writes both or neither, and 0024 nulls both when not registered). Name-only and rate-only cases are tested.
- **Validation:** timezone from `Intl.supportedValuesOf("timeZone")`; currency `z.enum(["MYR","SGD"])`, kept equal to `COUNTRY_DEFAULTS` by a test. Locale and date format are left off the page until Q10 (no invented list).
- **No-JS:** a save re-renders from the stored row (no redirect, so no 307). On a refusal, `echo` returns only the short code, timezone, currencies, the Yes/No, and the tax name and rate. The address, number, TIN and BRN are never echoed; they show their stored values. React escapes the echoed values.
- **"Applies to new documents only":** a hint on the base currency and the tax question. `newDocumentsOnly` compares before and after for the base currency and the tax fields (spec lines 460 and 731).
- **Refactor:** onboarding now uses the shared `TaxFields`, `taxAnswerFromForm` and `echoFields`. The `onboarding.spec.ts` change is one assertion line, and the onboarding unit tests pass unchanged.
